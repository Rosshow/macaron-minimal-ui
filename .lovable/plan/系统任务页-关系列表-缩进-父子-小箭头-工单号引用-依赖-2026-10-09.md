# 系统任务页：关系列表（缩进 = 父子，小箭头 / 工单号引用 = 依赖）

按最新一版需求：不画长连线，简单依赖用卡片之间的小箭头，复杂依赖用卡片顶部一行工单号引用。保留现有页面框架、搜索、筛选、排序和卡片风格。仅前端示例数据，不接后端，不加新建/派单/编辑。

## 核心规则
- 父子关系只用缩进：桌面每层 24px，手机 16px；同层左边缘对齐；子卡片字号不缩小。无树线、括号、容器框、「父/子」标签。
- 简单依赖（线性链且可紧邻排列）：卡片间距收紧到 12–16px，两卡之间一个小向下箭头（前置 → 后置），对齐这组卡片中心。无依赖的相邻卡片不显示箭头。
- 复杂依赖（多前置/多后置、跨父工单组、无法紧邻、被折叠或筛掉）：在卡片顶部信息行右侧显示一行摘要，如 `#235 → #286 → #307`。
  - 只显示直接前置、直接后置各最多一个；更多用省略号（前置侧在左，后置侧在右），如 `… #235 → #286 → #307 …`。
  - 选取顺序稳定（按工单号）。无「前置/后置」文字，靠箭头方向。
  - 单行、小字号、限宽；空间不足时减少工单号并用省略号；不增加卡片高度，不挤压状态、优先级、关注按钮，手机端同样不换行。
  - 当前工单号为中性灰；其他工单号为品牌链接色，点击直接进入该工单详情（不触发当前卡片打开）。可键盘操作，有可访问名称。
  - 不在当前结果中/无权限的工单不生成链接、不显示其信息。
- 同一条依赖不重复表达：已用小箭头表达的方向，顶部摘要不再重复；折叠/筛选使相邻不成立时，改为顶部引用。不把隐藏子工单的依赖转接到父工单。

## 1. 视图切换
- 筛选区下方：「普通列表 / 关系列表」+「全部展开 / 全部折叠」。
- 普通列表：保留原排序，不重排，依赖全部用顶部引用。
- 关系列表：保持父子结构，在同一父工单内把简单依赖链连续排列；绝不把子工单移出父工单。

## 2. 父子折叠
- 只有真实父工单有加号/减号按钮（aria-expanded），显示「子工单 1/3 已完成」。
- 折叠隐藏全部后代及其内部小箭头；嵌套折叠，重新展开保留内部状态；轻量动画，尊重减少动态效果设置。
- 不为依赖链虚构父工单或分组。

## 3. 卡片与状态
- 保留编号、标题、状态、优先级、创建人、处理人和原有关注按钮。
- 依赖展示不改变业务状态，不禁用查看/处理。
- 折叠按钮、工单号链接点击不打开当前卡片；不依赖鼠标悬停。

## 4. 示例数据（9 种场景）
独立工单；纯父子组；多层父子；三张子工单组成的简单链（#100 下 #235→#286→#307）；多前置指向一张；一张指向多后置；跨父工单组依赖；同时有链内依赖和额外复杂依赖；需要省略号的多依赖工单。状态覆盖待处理/处理中/已完成。

## 技术说明
- `src/data/task-relations.ts`：工单 + 结构化 `parentEdges`、`dependencyEdges`（详情页可通过现有 `/tickets/$id` 打开）。
- `src/lib/task-graph.ts`：构建树、同父兄弟内识别可紧邻的线性链并排序、按当前可见列表计算每张卡的「相邻箭头」与「顶部摘要」（去重、稳定选取、省略号）；配测试（多前置不成串行、折叠不转接父工单、同一依赖不重复、子工单不移出父工单）。
- `src/components/tasks/RelationList.tsx`：缩进渲染与折叠；`DependencySummary` 单行组件（容器宽度测量后逐级减少工单号）。
- `tasks.tsx`：加切换与按钮，扩展现有 `TicketCard` 顶部行放摘要。
